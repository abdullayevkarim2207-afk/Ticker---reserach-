1:39 - Return estimates and annualization

The estimate function validates dates and positive price fields, calculates
simple monthly returns, and supports either all 60 returns or the most recent
36. It annualizes the arithmetic monthly mean by multiplying by 12 and
annualizes sample volatility and covariance consistently. These are historical
estimates, not forecasts.

2:00 - Covariance validation and portfolio search

The covariance function first refuses missing, asymmetric, or out-of-range
correlations. It converts correlation to covariance using both asset
volatilities. The portfolio calculation evaluates the complete covariance
quadratic form, including cross-asset terms.

The search then enumerates every fully invested, long-only combination in
five-percentage-point increments. It rejects portfolios below the return or
reserve requirements and keeps the feasible portfolio with the lowest
volatility. If none is feasible, it returns no result instead of silently
relaxing the mandate.

3:03 - Standard-library runner and baseline verdicts

The standard-library runner connects the same saved data and engine to the
visible committee result. Equal weight and inverse volatility fail the return
rule. The 60/40 benchmark fails the reserve rule. The constrained mix passes
the encoded subset at 65% SGOV and 35% VT, with a 6.58% historical return
estimate and 5.29% volatility.

3:39 - Stress package and explicit stop condition

The stress package changes four risk surfaces. Reducing VT's estimate by one
percentage point and applying a 25-basis-point annual cost each move the
allocation by five points. Changing the window to the last 36 returns moves
SGOV and VT by 20 points, failing the 10-point stability limit. Raising the
reserve minimum to 70% produces no feasible portfolio and triggers the explicit
stop condition.

4:09 - Automated tests and decision-test failure

These are the terminal results. The technical validation passes 31 automated
tests covering known answers, malformed inputs, baseline verdicts, saved
scenarios, and app controls. The software test passes because it correctly
detects the failure, while the investment decision test fails: the 20-point
window change exceeds the allowed limit.

4:27 - Limitations and technical conclusion

The app does not establish future return, issuer concentration, five-day
liquidity, turnover, or the undefined calendar-loss promise. Those limitations
block live use. The defensible technical conclusion is that the system is
reproducible and useful for a monitored paper pilot, but it is not validated
for a client-capital allocation.
